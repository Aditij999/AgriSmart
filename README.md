## Setup & Run (Step-by-Step)

### 1. Install dependencies
```bash
pip install pandas numpy scikit-learn joblib streamlit plotly requests python-dotenv
```

### 1a. Chat assistant — hybrid intent classifier + Gemini API
The dashboard includes a floating 💬 chat button (bottom-left of the
screen). Click it to open a chat panel that answers questions about
whatever crop/soil/fertilizer/yield results are currently on screen.

It answers in two stages:
1. **Intent classifier (instant, free, offline).** The original TF-IDF +
   logistic regression classifier (`chatbot/classifier.py`,
   `chatbot/intents.json`) is tried first. If it's confident about what's
   being asked, `chatbot/intent_responder.py` answers immediately from a
   template filled in with your actual results — no API call.
2. **Gemini API (fallback).** Anything the classifier isn't confident about
   — an unusual phrasing, a more open-ended question — is handed to the
   Gemini API instead, using this run's results as context.

Both stages are restricted to crop recommendation, soil, fertilizer, and
yield topics: a confident off-topic match is refused instantly by the
classifier stage, and Gemini has its own instructions to decline anything
else even if the classifier lets it through. This routing lives in the new
`chatbot/router.py`.

Get a free Gemini API key at https://aistudio.google.com/apikey, then put
it in the `.env` file at the project root (already created for you):
```
GEMINI_API_KEY=your-key-here
```
`app.py` loads `.env` automatically on startup via `python-dotenv`, so no
manual export is needed. `.env` is git-ignored, so your key won't get
committed. `.env.example` shows the expected format. Without a key, the
chat still works for anything the intent classifier can answer directly;
only the Gemini fallback needs it (a "no key configured" message shows up
only when a question actually needs that fallback). A key can also be a
real environment variable, a Streamlit secret (`.streamlit/secrets.toml`),
or pasted into the chat panel's own "Gemini API key" box (session-only,
not saved to disk).

The old CLI chatbot (`chatbot/chatbot.py`, `chatbot/context.py`) is no
longer wired into the app — it read a report_*.json file from `outputs/`
and is superseded by the in-app flow — but `classifier.py`,
`intents.json`, and (a rewritten) `response_engine.py`-equivalent
(`intent_responder.py`) are now the app's primary answer path, not just
leftovers.

### 2. Train the crop recommendation model (Phase I)
```bash
python crop_model.py
```
This generates `models/crop_model.pkl`.

### 3. Train the yield prediction model (Phase II)
```bash
python modules/yield_model.py
```
This generates `models/yield_model.pkl`.

### 4. Run the full pipeline (console output)
```bash
python pipeline.py
```

### 5. Launch the Streamlit web app
```bash
streamlit run app.py
```
The dashboard (crop recommendation, soil analysis, fertilizer plan, yield
prediction, and the chat assistant) works standalone with no backend
running, exactly like before.

### 5a. Optional: connect the website to the same backend as the mobile app
Start the FastAPI backend as well:
```bash
uvicorn backend.main:app --reload
```
With it running, the website gains the same account system, saved history,
and compare feature as the Flutter mobile app — log in (or register) from
the "🔐 Account" panel near the top of the page, and a "📜 History &
Compare" section appears below your results to save runs, browse past
ones, and compare 2–4 — with a plain-language summary of what changed (soil readings, recommended crop, yield, fertilizer, soil status) above the field-by-field table. Runs saved from the website and the
mobile app show up in the same account's history either way. If the
backend isn't reachable, that section just says so and the rest of the
dashboard keeps working locally.

By default the website looks for the backend at `http://127.0.0.1:8000`;
override with `API_BASE_URL=http://your-host:8000 streamlit run app.py`.

### 5b. Chat assistant language
The chat assistant (in both the website and the mobile app) replies in
whichever language you write in — English, Hindi, or Marathi — by
default. Use the language chips above the chat box to force a specific
reply language instead.

### 5c. Chat assistant voice
Both the website and the mobile app can speak and listen: tap the mic to
dictate your question instead of typing it, and tap "🔊 Listen" under any
reply to have it read aloud. The mobile app uses on-device speech
recognition and text-to-speech (`speech_to_text` / `flutter_tts`); the
website uses the browser's built-in Web Speech API instead. Either way, no
audio is ever sent to a server — only the text that was already crossing
the browser/app boundary is.

## What Each Module Does

| Module | File | Type | Output |
|--------|------|------|--------|
| Crop Recommendation | `crop_model.py` | ML (Random Forest Classifier) | Top 5 crops + probabilities |
| Soil Adjustment | `modules/soil_adjustment.py` | Formula-based (Δ = Ideal − Current) | Nutrient gap + action |
| Fertilizer Recommendation | `modules/fertilizer_recommendation.py` | Rule-based system | Fertilizer name + dosage |
| Yield Prediction | `modules/yield_model.py` | ML (Random Forest Regressor) | Expected yield in kg/ha |
| Full Pipeline | `pipeline.py` | Orchestration | JSON report in outputs/ |
| Web UI | `app.py` | Streamlit | Interactive dashboard |

## Resume Description (Copy-Paste Ready)

**Soil Nutrient Analysis for Crop Planning and Fertilizer Recommendation**  
*Python · scikit-learn · pandas · Streamlit · Random Forest*

- Built a 4-module decision support system for precision agriculture targeting Black Soil regions of Western Maharashtra
- Trained a Random Forest Classifier (99% accuracy) to recommend optimal crops from N, P, K, pH, temperature, and rainfall inputs
- Designed a rule-based Soil Adjustment Engine computing nutrient gaps (Δ = Ideal − Current) with actionable increase/decrease/optimal flags
- Implemented a structured Fertilizer Recommendation module mapping multi-nutrient deficiencies to specific fertilizers (Urea, DAP, MOP, Lime)
- Developed a yield regression model (Random Forest, R² = 0.93) predicting expected output in kg/ha
- Deployed an end-to-end interactive web application using Streamlit with real-time sliders, Plotly charts, and auto-generated JSON reports
